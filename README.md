# Кадастровый Сервис (FastAPI + PostgreSQL + Redis + Docker)

Веб-сервис для проверки кадастровых номеров с микросервисной архитектурой, встроенным эмулятором внешних ответов, кэшированием результатов и JWT-авторизацией на схеме HTTP Bearer.

## Архитектура проекта

Проект разделен на два независимых сервиса согласно требованиям ТЗ:
1. **Главный сервис (FastAPI)** (`port 8000`) — отвечает за регистрацию, аутентификацию пользователей, валидацию входных данных, сохранение истории запросов в PostgreSQL и кэширование ответов эмулятора в Redis.
2. **Сервис-эмулятор (External Web)** (`port 8001`) — имитирует внешнее API госорганов. Содержит эндпоинт `/result`, который засыпает на случайное время (от 5 до 15 секунд) и возвращает случайный статус проверки (`true`/`false`).

### Логика работы эндпоинта `/query`:
1. Приложение проверяет наличие кадастрового номера в кэше **Redis**. Если кэш валиден — результат отдается мгновенно.
2. Если в кэше данных нет, отправляется асинхронный запрос к **Сервису-эмулятору**.
3. Полученный ответ сохраняется в **PostgreSQL** с привязкой к аккаунту сделавшего запрос пользователя.
4. Результат кэшируется в **Redis** на время, заданное в `REDIS_TTL`.

## Реализованные эндпоинты

### Главный сервис (`http://localhost:8000/docs`):
* `POST /auth/register` — Регистрация нового пользователя (принимает JSON c `email` и `password`).
* `POST /auth/login` — Аутентификация пользователя и выдача JWT-токена (принимает JSON c `email` и `password`).
* `GET /ping` — Проверка работоспособности бэкенда.
* `POST /query` — Отправка кадастрового номера на проверку (требует JWT-токен в заголовке `Authorization: Bearer`).
* `GET /history` — Получение истории запросов текущего авторизованного пользователя.

### Сервис-эмулятор (`http://localhost:8001/docs`):
* `POST /result` — Внутренний эндпоинт, имитирующий долгую обработку запроса госорганами.

## Стек технологий
* **Python 3.13** / **FastAPI** / **Uvicorn**
* **uv** (современный и быстрый менеджер пакетов)
* **SQLAlchemy 2.0** (Asyncio / `async_sessionmaker`)
* **PostgreSQL** (Хранение пользователей и логов запросов)
* **Redis** (Временное кэширование ответов эмулятора)
* **PyJWT** (Авторизация через заголовок Bearer Token)
* **Docker** & **Docker Compose** (Контейнеризация всей инфраструктуры)
* **Pytest** + **HTTPX AsyncClient** (Автоматическое тестирование API, моделей и схем)

## Инструкция по быстрому запуску

### 1. Подготовка окружения
Создайте файл `.env` в корневом каталоге проекта. Пример наполнения:
```env
POSTGRES_DB=cadastre_db
POSTGRES_USER=postgres
POSTGRES_PASSWORD=postgres
POSTGRES_HOST=db
POSTGRES_PORT=5432
DATABASE_URL=postgresql+asyncpg://postgres:postgres@db:5432/cadastre_db

REDIS_HOST=redis
REDIS_PORT=6379
REDIS_TTL=600

EXTERNAL_SERVER_URL=http://external_web:8001/result
SECRET_KEY=your_secret_key_here
ALGORITHM=HS256
```

### 2. Запуск контейнеров
Запустите сборку и поднятие всей инфраструктуры в фоновом режиме:

```Bash
docker compose -f docker-compose.dev.yaml up -d --build
```
После этого интерактивная документация Swagger будет доступна по адресу: http://localhost:8000/docs.

### 3. Запуск тестов
Проект полностью покрыт интеграционными и unit-тестами (API, модели SQLAlchemy, валидация схем Pydantic).
Запуск внутри Docker-контейнера:
```Bash
docker exec -it fastapi_app_dev pytest tests/ -v
```
Запуск локально (требуется установленный uv):
```Bash
uv run pytest tests/ -v
```

### 4. Остановка проекта
Чтобы остановить контейнеры и очистить окружение:

```Bash
docker compose -f docker-compose.dev.yaml down
```
